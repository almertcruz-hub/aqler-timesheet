Part 1

The whole application flow

Most actions in the app follow the same path:

User clicks or types
React handler runs
Supabase query runs
Postgres checks RLS
React stores result
Screen renders again
Simple meaning

React controls the browser interface. Supabase provides authentication and the database. Row Level Security decides which database rows the signed-in user may read or change.

The current design stores one whole work session in one logs row. Time In inserts it with a null time_out; Time Out updates that same row. The row can therefore show both times, shift date, duration, and status together.

Part 2

JavaScript values and functions

1const stores a returned value
const timer = setTimeout(loadLogs, 400)
What runs?

JavaScript first calls setTimeout(...). That call schedules loadLogs and returns a timer ID. Then const timer stores that ID. Declaring const is not what starts the timer; evaluating the function call on its right side starts it.

2Named and anonymous functions
function loadLogs() {
  console.log('Loading')
}

const loadProfiles = () => {
  console.log('Loading profiles')
}

// An anonymous function passed to React:
() => {
  loadLogs()
}

The first function is named directly. The second arrow function is stored in loadProfiles. The last function has no name because it is being handed directly to another function to call later.

Why does onClick receive a function? 
onClick={() => startEditing(shift)}

React needs instructions it can call later, when the click happens. Writing onClick={startEditing(shift)} would call the function immediately during rendering and assign its returned value to onClick.

3Transform an array with map
const employeeIds = profiles.map((profile) => profile.id)

const employees = profiles.map((profile) => ({
  id: profile.id,
  full_name: profile.full_name,
  email: profile.email,
}))

map returns one new item for every original item. The first example returns only each ID. The second returns a new object containing all three selected properties.

4Extract values with destructuring
const { data, count, error } = await query

This is a shorter way to write:

const result = await query
const data = result.data
const count = result.count
const error = result.error

Part 3

How React builds and changes the interface

Components and JSX

function EmployeeName({ name }) {
  return <p>{name}</p>
}

A component is a JavaScript function that returns JSX. JSX resembles HTML, but braces insert JavaScript values into the interface.

Why two inner div elements are side by side

<div className="flex items-center gap-2">
  <div>Avatar</div>
  <div>Email and role</div>
</div>

A div is a general container. The outer container is the parent. Tailwind's flex class tells that parent to arrange its direct children in a horizontal row by default. gap-2 adds space between them.

State

const [page, setPage] = useState(1)
PartMeaning
pageThe current value.
setPageThe function that requests a new value.
1The initial value on the first render.

Calling setPage(2) causes React to render the component again with page equal to 2.

Conditional rendering

{isAdmin && <button>Edit shift</button>}

When isAdmin is true, the button is included. When false, nothing is rendered there. This improves the interface, but RLS must enforce the actual security rule.

What does the Tailwind md: prefix mean? 
<div className="flex flex-col md:flex-row">

The layout is a vertical column by default. Starting at Tailwind's medium breakpoint, md:flex-row changes it into a horizontal row. Tailwind is mobile-first: unprefixed classes apply first, and breakpoint variants override them on wider screens.

Part 4

Effects and debounced search

useEffect(() => {
  const timer = setTimeout(() => {
    setDebouncedSearch(search)
    setPage(1)
  }, 400)

  return () => {
    clearTimeout(timer)
  }
}, [search])
  1. React renders the component.
  2. If search changed, React calls the function passed to useEffect.
  3. setTimeout schedules its inner function for 400 milliseconds later.
  4. If the user types again first, React runs the cleanup function.
  5. clearTimeout(timer) cancels the previous scheduled callback.
  6. Usually only the latest search reaches setDebouncedSearch.
Does every effect return something? No. The return value is optional. Return a cleanup function only when the effect created something that should be cancelled, unsubscribed, or removed.
Why does useEffect need a function inside it?

Calling useEffect registers work with React. The inner function is the work React should run after rendering. If you performed the work before passing it, it would run during render instead of at the correct point in React's lifecycle.

Part 5

Reading data from Supabase

const { data, error } = await supabase
  .from('logs')
  .select('*')
CodeMeaning
.from('logs')Choose the logs table.
.select('*')Request all permitted columns. The star does not bypass filters or RLS.
dataThe rows returned after filters and RLS.
errorAn error object, or null when successful.

Filtering combined search text

.ilike('search_text', `%${search}%`)

The reporting view prepares one search_text value from the employee and work-session fields. ilike is a case-insensitive “contains” filter that runs in Postgres before rows reach the browser.

Why a view helps the admin-log search

Work-log fields live in logs, while names and emails live in profiles. A view joins them and exposes a flat result where all searchable fields behave like columns of one source. 

supabase
  .from('admin_work_logs')
  .select('*', { count: 'exact' })
  .ilike('search_text', `%${search}%`)
Simple meaning The one search input stays the same. The view makes the database result easier to search, count, paginate, and export because the joined fields appear together.

Part 6

Server-side pagination

const from = (page - 1) * pageSize
const to = from + pageSize - 1

const { data, count, error } = await supabase
  .from('admin_work_logs')
  .select('*', { count: 'exact' })
  .range(from, to)

data contains only the requested page. count contains the exact number of rows matching the query before the page range is applied.

Example valueResult
87 matching database rowscount === 87
Page size 20, first pagedata.length === 20
Total pagesMath.ceil(87 / 20) === 5

Every Next or Previous click changes page. If the loading effect depends on page, React runs it again and sends a new query. This is desirable: the browser downloads only the page it needs instead of thousands of rows.

Export should be separate The screen query remains at 20 rows. The current CSV export runs its own admin_work_logs requests in batches of 1,000 until it has every search match, so it is not limited to the visible page.

Part 7

Authentication and Row Level Security

Identify the signed-in user

user_id = (select auth.uid())

In a policy, auth.uid() returns the signed-in user's UUID. This condition passes only when the database row belongs to that user.

Check the administrator role

(select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin'

auth.jwt() exposes token claims. -> reads a JSON object, while ->> reads the final value as text.

Set administrator metadata

update auth.users
set raw_app_meta_data =
  coalesce(raw_app_meta_data, '{}'::jsonb)
  || '{"role":"admin"}'::jsonb
where lower(email) = lower('admin@example.com');
  • jsonb is Postgres's searchable binary JSON format.
  • coalesce uses the first value that is not null.
  • || merges the JSON objects; the right-side role replaces an existing role.
  • The user must sign out and in to receive a refreshed JWT.

GRANT, USING, and WITH CHECK

PartQuestion it answers
GRANTMay this database role attempt the table operation?
USINGWhich existing rows may the user see, update, or delete?
WITH CHECKIs the newly inserted or updated row allowed?
How do permissive and restrictive policies combine?

Applicable permissive policies combine like OR: passing one may allow the row. Applicable restrictive policies combine like AND: every restrictive condition must pass, in addition to at least one permissive policy.

Never depend on hidden buttons for security React controls what the user sees, but requests can be sent without the interface. RLS is the layer that must reject unauthorized database work.
